# Working notes

Use a tracked note only for a handoff, incident, experiment, or coordination that
needs to survive a session. Start from the [work-note form](../templates/WORK_NOTE.md).
Disposable scratch belongs in ignored `.work/`.

Give every note an owner, purpose, status, review/delete date or milestone, and
links to evidence. Record observations, decisions, unresolved questions and next
actions; do not store transcripts or hidden reasoning. Use synthetic cases and
sanitized counts rather than caller data, private labels, raw logs, secrets or
identifying hashes. Review content before committing to this public repository.

Promote stable conclusions into code/tests, the plan, an ADR, or dated project
memory. On closure, remove obsolete notes or replace them with a short pointer to
the durable record. Git and PR history provide the change history; do not build a
second chronological task ledger here. Josh Myers owns review of retained notes
before each release and the note's stated milestone.
